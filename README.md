# practice-sns

Java와 Spring Boot 학습을 위해 만든 SNS 프로젝트입니다.
RESTful API(`/api/**`)와 Thymeleaf 서버사이드 렌더링을 함께 사용합니다.

## 🛠 기술 스택

- **Java 21**, **Spring Boot 3.4.5**, Gradle
- Spring Data JPA + **MySQL**
- Spring Security + **JWT**(jjwt 0.12.5) — httpOnly 쿠키 기반 인증, 리프레시 토큰으로 자동 갱신
- **WebSocket** — DM 실시간 푸시
- Thymeleaf, Lombok
- 테스트: **JUnit 5**, Mockito, MockMvc, **H2**(인메모리)

## 📌 주요 기능

### 👤 사용자

#### 🟢 회원가입 ✅
- `id`, `password`를 전달받아 처리
- `id` 조건
  - 4~10자
  - 영어 소문자, 숫자, `.`, `_` 사용 가능
  - 숫자로만 구성될 수 없음
  - `.`, `_`가 연속되거나 맨 앞·뒤에 올 수 없음
- `password` 조건
  - 8~15자
  - 대문자, 소문자, 숫자, 특수문자 **모두** 포함
- `id` 중복 확인 후 DB에 저장
- 검증 실패 시 `GlobalExceptionHandler`가 400과 안내 문구를 반환

#### 🔐 로그인 / 로그아웃 ✅
- `id`, `password` 검증 후 액세스 토큰과 리프레시 토큰 발급
- 토큰은 **httpOnly 쿠키(`JWT_TOKEN`, `REFRESH_TOKEN`)** 로 내려가며, 이후 모든 요청에 자동으로 실려 인증에 사용됨
- 액세스 토큰이 만료돼도 리프레시 토큰이 살아 있으면 다시 로그인하지 않아도 됨 ([인증 방식](#-인증-방식) 참고)
- 로그아웃 시 쿠키를 만료시키고, 서버에 저장된 리프레시 토큰도 함께 삭제해 재발급을 차단

#### 🧑 프로필 기능 ✅
- 프로필 이미지, 닉네임 등 기본 정보 확인
- 닉네임 수정 가능 (본인 프로필에서만 수정 버튼 노출)
  - 닉네임 변경 시 JWT를 새로 발급해 쿠키를 갱신
- 프로필 하단에 해당 사용자가 작성한 게시물 피드 표시
- 프로필 URL은 닉네임이 아닌 **userId** 기준 (`/profile/{userId}`)

#### 🤝 팔로우 ✅
- 프로필에서 팔로우 / 언팔로우 (토글)
- 팔로워 · 팔로잉 수 표시, 숫자를 누르면 목록 모달로 확인
- 피드 상단 **전체 / 팔로잉** 탭 — 팔로잉 탭은 내가 팔로우한 사용자의 게시물만 표시
- 자기 자신, 정지된 사용자는 팔로우할 수 없음
- `(follower, following)` 복합 유니크 제약으로 중복 팔로우를 DB에서 차단

#### ❌ 회원탈퇴 기능 ✅
- 로그인한 사용자가 자신의 계정을 삭제
- 탈퇴 시 관련 데이터 **모두 삭제** (게시물 / 댓글 / 좋아요 / 팔로우 / 알림)
- 탈퇴 후 쿠키 만료로 자동 로그아웃 처리

### 📝 게시물 / 💬 댓글 / ❤️ 좋아요

#### 게시물 ✅
- **제목 없이 내용과 사진**으로 작성 (인스타그램·X 스타일)
- 사진은 필수이며 `MultipartFile`로 업로드, MIME 타입 검증으로 이미지 파일만 허용
- 작성 / 조회 / 수정 / 삭제
- 수정은 작성자 본인만, 삭제는 작성자 본인 또는 관리자
- 전체 게시물 피드 조회, 피드에서 게시물 클릭 시 모달로 상세 보기
- 모달에서 작성자 닉네임 클릭 시 해당 작성자 프로필로 이동

#### 댓글 ✅
- 게시물에 댓글 추가
- 수정은 작성자 본인만, 삭제는 작성자 본인 또는 관리자
- 게시물의 전체 댓글 조회

#### 좋아요 ✅
- 게시물 및 댓글에 좋아요 추가 / 취소

#### 🏷 해시태그 ✅
- 게시물 본문의 `#태그`를 정규식으로 추출해 저장 (한글 · 영문 · 숫자 · `_`)
- 대소문자를 구분하지 않으며(`#Daily` = `#daily`), 한 게시물당 최대 30개
- 본문의 해시태그는 링크로 표시되고, 누르면 해당 태그의 게시물 목록으로 이동
- 게시물 수정 시 기존 연결을 지우고 본문 기준으로 다시 연결

### 🔔 알림 ✅

- 팔로우 / 게시물 좋아요 / 댓글이 발생하면 대상 사용자에게 알림 생성

- **알림 생성 정책**
  - 본인의 행동에는 알림을 만들지 않음
  - 팔로우 · 좋아요는 껐다 켜는 동작이므로 중복 알림을 만들지 않고, 취소 시 기존 알림을 삭제
  - 댓글은 여러 번 달 수 있으므로 매번 새로 생성

### 💬 DM (1:1 채팅) ✅

- 프로필의 **메시지 버튼**으로 대화 시작, 헤더의 로켓 아이콘으로 대화 목록 진입
- 방은 두 사람 조합당 하나 — 누가 먼저 열어도 같은 방 (복합 유니크 제약)
- **전송은 REST, 수신은 WebSocket 푸시** — 상대가 접속 중이면 새 메시지를 즉시 전달
  - 핸드셰이크가 일반 HTTP 요청이라 기존 JWT 쿠키 인증을 그대로 통과
  - 소켓이 끊긴 동안은 폴링이 대신 동작하고, 3초 후 자동 재연결
- **하트비트(ping/pong)** — 서버가 30초마다 신호를 보내고 클라이언트가 응답
  - 푸시 전용이라 평소 트래픽이 0인 연결이 조용하다는 이유로 끊기는 것을 방지
  - 90초 동안 응답이 없는 세션은 죽은 연결로 보고 정리 (클라이언트도 100초 침묵 시 소켓을 직접 닫아 재연결과 폴링을 재개)
- 헤더에 **안읽음 배지** — 어느 페이지에 있든 실시간 갱신
- **읽음 표시** — 상대가 읽는 순간 내 메시지의 체크 표시가 실시간으로 켜짐
- **메시지 수정 / 삭제** — 상대가 아직 읽지 않은 내 메시지만, 우클릭 메뉴로 처리
  - 삭제는 내용을 지우고 "삭제된 메시지입니다."로 표시, 수정한 메시지는 시간 옆에 "(수정됨)" 표기
  - 메뉴가 떠 있는 사이 읽힐 수 있으므로 서버가 읽음 여부를 최종 검증
- 메시지는 최신순 페이징으로 불러오고, "이전 메시지 보기"로 과거 내역 조회
- 자기 자신, 정지된 유저와는 대화할 수 없고, 참여자가 아니면 조회와 전송 모두 불가
- 회원 탈퇴 시 참여한 방과 메시지도 함께 삭제

## ⚡ 페이징과 쿼리 최적화

- 피드는 `Slice` 기반 페이징으로 조회하고, 화면에서는 **무한 스크롤**로 이어서 불러옴
- 초기에는 게시물마다 좋아요 수 · 좋아요 여부 · 댓글 수를 각각 조회해 **게시물 18건에 쿼리가 59번** 나갔음
- 게시물 id를 모아 종류별로 한 번씩만 조회하도록 바꾸고(`GROUP BY` 집계 + `IN` 조회), 작성자는 `JOIN FETCH`로 함께 조회하여 **쿼리 6번**으로 감소
- 정지 사용자 필터링도 자바 코드가 아닌 쿼리 조건으로 옮겨, 페이징 개수가 어긋나지 않도록 수정

## 🔑 인증 방식

- 로그인 성공 시 서버가 **액세스 토큰(JWT, 30분)** 과 **리프레시 토큰(14일)** 을 발급해 각각 **httpOnly 쿠키**로 설정
- 인증 판정은 `JwtAuthFilter` 한 곳에서만 수행 — 컨트롤러는 `@AuthenticationPrincipal`로 결과만 받아 사용
- 클라이언트(브라우저)는 토큰을 직접 보관하지 않으며, 로그인이 필요한 페이지(예: 게시글 작성)는 서버에서 접근을 제어
- 인증 실패는 `AuthenticationEntryPoint`에서 **비로그인(401)** 과 **계정 정지(403)** 로 구분해 응답

#### 액세스 토큰 자동 갱신 ✅

- 액세스 토큰이 만료돼도 리프레시 토큰이 유효하면 **`JwtAuthFilter`가 새 액세스 토큰을 발급하고 요청을 그대로 진행**
  - 별도의 갱신 엔드포인트를 두지 않은 이유는 Thymeleaf 서버사이드 렌더링 때문 — 페이지는 서버가 HTML을 만드는 시점에 로그인 여부가 확정되므로, 브라우저가 401을 받고 재시도하는 방식으로는 "오랜만에 접속해도 로그인 유지"를 만들 수 없음
- 리프레시 토큰은 JWT가 아닌 **난수 문자열**이며, DB에는 **SHA-256 해시**로만 저장 (취소 가능해야 하므로 자기 자신만으로 유효한 JWT를 쓰지 않음)
- **회전(rotation)** — 갱신할 때마다 리프레시 토큰도 새로 발급하고 이전 것은 교체 표시
  - 한 페이지에서 요청이 동시에 나가면 모두 같은 토큰으로 갱신을 시도하므로, 교체 직후 **60초간은 이전 토큰도 인증만 허용**해 정상 사용자가 로그아웃되지 않도록 처리
  - 회전 판정은 `UPDATE ... WHERE replaced_at IS NULL`로 DB에 위임 — 동시 요청이 각자 새 토큰을 만들어 쓰이지 않는 토큰이 쌓이는 것을 방지
  - 만료 시각은 최초 로그인 기준을 유지해 갱신으로 수명이 무한히 늘어나지 않도록 함
- **로그인 단위 관리** — 로그인 한 번을 하나의 묶음(`familyId`)으로 보고, 로그아웃 시 회전으로 파생된 토큰까지 함께 삭제. 다른 기기의 로그인은 유지
- 정지 계정은 리프레시 토큰으로도 인증되지 않으며, 인증에 실패한 경우 토큰을 회전시키지 않아 정지 해제 후 로그인 상태가 유지됨

## ▶️ 실행 방법

1. MySQL에 데이터베이스 생성
   ```sql
   CREATE DATABASE sns_db CHARACTER SET utf8mb4;
   ```

2. 프로젝트 루트의 `secrets.properties.example` 을 `secrets.properties` 로 복사하고 값 채우기 (git에 포함되지 않음)
   ```properties
   DB_USERNAME=<DB 사용자명>
   DB_PASSWORD=<DB 비밀번호>
   # HS256 서명용 랜덤 키, 32바이트 이상. 생성 예: openssl rand -base64 48
   JWT_SECRET=<시크릿 키>
   ```
   나머지 설정은 `src/main/resources/application.properties` 에 있으며, 시크릿 자리만 `${...}` 로 비워져 있다.
   배포 환경에서는 파일 대신 같은 이름의 환경변수를 설정하면 우선 적용된다.

3. 애플리케이션 실행
   ```bash
   ./gradlew bootRun
   ```
   실행 후 `http://localhost:8080` 접속
